# Provider and router configuration

RepoArena runs coding-agent CLIs inside isolated Docker containers. It does not call model APIs on
the host, store API keys, proxy inference through a RepoArena service, or pay provider charges.
Enable only the agents you intend to benchmark.

## Credential rules

- Set API keys in the shell that launches RepoArena.
- Put only environment variable **names**, never secret values, in `.repoarena/config.toml`.
- RepoArena forwards a selected key only to that solver container. The value is kept out of Docker
  command arguments, logs, SQLite, patch files, reports, and verifier containers.
- A provider or router can still receive task text and repository code through its coding agent.
  Review that service's data policy before benchmarking private code.

## Gemini CLI

Enable Gemini and provide a Google Gemini API key:

```toml
[agents.gemini]
enabled = true
model = "gemini-model-id"
```

macOS/Linux:

```bash
export GEMINI_API_KEY="your-key"
repoarena doctor
repoarena benchmark --agent gemini
```

Windows PowerShell:

```powershell
$env:GEMINI_API_KEY = "your-key"
repoarena doctor
repoarena benchmark --agent gemini
```

The adapter uses [Gemini CLI](https://github.com/google-gemini/gemini-cli) headless streaming JSON
mode and automatically approves tools only
inside RepoArena's bounded solver container. Google account sign-in and Vertex AI authentication
are not claimed as validated in 0.1.1; API-key authentication is the supported path.

## OpenRouter

OpenRouter is executed through [OpenCode](https://opencode.ai/docs/cli/) headless coding agent, not
as a one-shot chat request. OpenRouter documents its API as
[OpenAI-compatible](https://openrouter.ai/docs/quickstart).
Choose an OpenRouter model slug and keep the default endpoint:

```toml
[agents.openrouter]
enabled = true
model = "provider/model-id"
base_url = "https://openrouter.ai/api/v1"
api_key_env = "OPENROUTER_API_KEY"
```

Then set `OPENROUTER_API_KEY` in the launching shell and run:

```bash
repoarena doctor
repoarena benchmark --agent openrouter
```

RepoArena does not guess OpenRouter cost. A report shows `Cost: unavailable` unless the underlying
CLI emits an exact monetary value in a supported structured event.

## 9Router and other OpenAI-compatible routers

The generic `router` adapter defaults to the standard
[9Router](https://github.com/decolua/9router) host endpoint. `host.docker.internal`
is intentional: `localhost` inside the solver refers to the solver container, not the host.

```toml
[agents.router]
enabled = true
image = "repoarena/opencode:local"
executable = "opencode"
provider_id = "router"
base_url = "http://host.docker.internal:20128/v1"
api_key_env = "ROUTER_API_KEY"
model = "router-model-id"
allowed_domains = ["host.docker.internal"]
```

Set the API key generated by your router dashboard:

```powershell
$env:ROUTER_API_KEY = "your-router-key"
repoarena doctor
repoarena benchmark --agent router
```

If 9Router uses another port, such as `20129`, change only `base_url`. For a remote compatible
router, use HTTPS and make `allowed_domains` cover exactly that endpoint's hostname:

```toml
base_url = "https://router.example.com/v1"
allowed_domains = ["router.example.com"]
api_key_env = "MY_ROUTER_API_KEY"
```

Plain HTTP is accepted only through `host.docker.internal`. Keep local routers updated, API-key protected,
bound as narrowly as practical, and blocked from untrusted network clients. RepoArena does not
manage or harden the router process itself.

## Reproducible CLI images

The image build scripts accept independent version pins:

```bash
CODEX_VERSION=x CLAUDE_VERSION=x GEMINI_VERSION=x OPENCODE_VERSION=x \
  sh ./scripts/build-images.sh
```

```powershell
.\scripts\build-images.ps1 `
  -CodexVersion x -ClaudeVersion x -GeminiVersion x -OpenCodeVersion x
```

Use versions you have validated for your organization. Real-provider tests remain opt-in and normal
RepoArena CI does not consume paid API calls.
